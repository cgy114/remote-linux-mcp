# remote-mcp 安全威胁模型（P5）

本文描述 remote-mcp 在“本地 MCP 客户端 → SSH 主机”路径上的资产、信任边界、对手模型、
已知可绕过项与残余风险。它是运营决策的依据，不是“已完全防护”的声明。

## 1. 资产

| 资产 | 位置 | 影响 |
| --- | --- | --- |
| SSH 私钥 / agent 中的密钥 | 本地 | 可登录受管主机 |
| sudo 密码 | 系统凭据库 + 进程内存 | 可提权执行任意命令 |
| 远端命令输出、文件内容 | 本地进程内存 / 结果 | 泄露业务数据、配置、密钥 |
| known_hosts / trust registry | 配置目录 | 主机身份与中间人防护 |
| 审计日志 | 配置目录 `audit.jsonl` 与归档 | 事后追溯；被篡改会失去证据 |
| 本机账户权限 | 本地 | 读取配置、凭据库、审计、内存的最终边界 |

## 2. 信任边界

1. **MCP 客户端 ↔ remote-mcp 进程**：stdio。客户端可以提交任意工具参数；服务端必须把
   所有输入视为不可信（zod strict schema、大小限制、策略求值、路径 deny）。
2. **remote-mcp ↔ 本地操作系统**：凭据库、配置文件、审计目录、`ssh` 子进程。本机同一用户
   下的其他进程不在隔离边界内。
3. **remote-mcp ↔ 远端 sshd / shell**：SSH 加密通道保护传输，但远端 shell、sudoers、
   profile、别名与命令本身都可能是攻击面。
4. **配置目录 ↔ 备份/同步工具**：审计与 trust registry 可能被云盘、备份、同步软件复制到
   本机之外。

## 3. 对手模型

- **恶意/被诱导的 MCP 客户端或提示注入**：试图让模型执行危险命令、读取敏感文件、把秘密
  写入输出或审计。
- **本机低权限进程/其他用户**：试图读取凭据、配置、审计或注入环境变量。
- **网络中间人**：试图冒充远端主机（由 pinned host key + `remote-mcp trust` 防护）。
- **被攻陷的远端主机**：可以伪造输出、在 sudo 提示中注入文本、留下后台进程、读取通过
  stdin/命令行传入的内容。
- **拥有当前用户权限的攻击者**：可以读取进程内存、修改配置与审计、替换 `ssh` 可执行文件。
  这是本工具的**最终信任边界**，无法在用户态彻底防御。

## 4. 策略可绕过项（重要）

命令策略（`security.command_policy`）与 sudo allow/deny 是**启发式减速带**，不是沙箱：

- **eval / source / shell 解释器**：`eval "$X"`、`. ./script`、`bash script.sh`、`python -c`、
  `perl -e`、`node -e`、`awk 'BEGIN{system(...)}'` 等可以执行任意代码。内置规则会拒绝
  部分解释器作为片段首词，但无法穷举所有包装器与语言运行时。
- **远端 profile / bashrc / 别名**：`bash -lc` 会加载登录 shell 配置；远端用户可定义别名、
  函数或 `PROMPT_COMMAND` 改变命令含义。策略在本地看的是文本，不是远端展开后的语义。
- **base64 / 编码解码**：`echo <b64> | base64 -d | sh`、`xxd -r`、`printf %b`、变量拼接、
  命令替换与进程替换都可以隐藏真实命令。`read_only` 会拒绝命令替换/反引号/进程替换与
  重定向，但 `enforce` 模式主要依赖 deny 规则。
- **路径与参数歧义**：`find -exec`、`xargs`、`env`、`nohup`、`timeout`、`nice`、`sudo` 等
  包装器会改变“首词”判断；`rm -rf "$DIR"` 的实际目标只能在远端解析。
- **多段命令**：`a && b`、`a; b`、管道会逐段扫描，但引号、转义、换行与别名仍可能改变分段。
- **sudoers**：远端 sudoers 的 `NOPASSWD`、`secure_path`、`env_keep` 决定实际可执行范围；
  本地 allow/deny 只是额外约束。
- **工具之外的通道**：客户端仍可直接使用 `ssh_exec` 的其他参数（env/cwd/stdin）或文件传输
  工具；策略覆盖的是命令文本，不是数据流向。

运营建议：把策略当作“防误操作 + 提高攻击成本”，不要把 `enforce` 当成强隔离；高价值主机
应在远端使用最小权限账户、sudoers 白名单、SELinux/AppArmor、审计与网络分段。

## 5. 只读不等于保密

`read_only` 模式只限制**修改型结构**（后台执行、重定向、命令替换、敏感 env、解释器/提权
程序），并不限制读取：

- `cat ~/.ssh/id_rsa`、`env`、`cat /etc/shadow`（若有权限）、`tar` 打包敏感目录都可能成功；
- `ssh_read_file` 的敏感路径 deny 是有限列表；`ssh_exec` 可以绕过它读取同一文件；
- 输出会进入 MCP 结果与客户端上下文，可能被日志、会话记录或模型提供方看到。

若数据本身敏感，应在远端做访问控制，而不是依赖本地 `read_only`。

## 6. 密码的内存残余

`sudo.mode=password` 的路径：

1. keyring 原生 API 返回 JavaScript `string`（无法原地清零），立即复制为 `Buffer`；
2. `SecretMaterial` 持有该 Buffer；`composeSudoStdin` 再复制一次以追加换行；
3. 子进程 stdin 写入后，composed Buffer 与 `SecretMaterial` 在 `finally` 中清零；
4. `loadSecret` 超时后，对迟到结果立即 wipe，避免明文长期停留。

仍存在的残余：

- JS 字符串、Buffer 扩容/复制、V8 堆与操作系统换页可能留下无法控制的副本；
- 本机同用户进程可以读取进程内存或使用调试器；
- 崩溃转储、休眠文件、EDR/遥测可能捕获内存；
- `credential status` 在 keyring 绑定没有“仅查元数据”API 的情况下会调用 `getPassword()` 判断是否存在；
  明文不会离开 provider、不会返回给 CLI，也不会打印，但会在原生库内部短暂存在。

因此：不要在不可信的本机上使用 password 模式；优先配置远端 `NOPASSWD` 的窄命令白名单。

## 7. 审计的同用户可修改性

- 审计文件位于配置目录，权限为 `0600`，但没有签名/链式哈希；
- **拥有当前用户权限的人或进程可以编辑、截断、删除 `audit.jsonl` 与归档**；
- 轮转/保留会删除旧归档，这是设计行为，不是审计丢失；
- 多进程（多个 remote-mcp 实例）同时写同一目录时，各进程只有本地串行链，**没有跨进程
  文件锁**，可能交错写入或同时轮转；极端情况下 rename 与 append 竞争会让个别记录落到
  归档或活动文件的边界。需要严格审计时应单实例运行，或把审计转发到受控的远端 sink。

运营建议：把配置目录放在受控位置；用文件完整性监控、远端 syslog、集中日志或 WORM 存储
保存副本；不要把审计当作防篡改证据链。

## 8. 后台任务不回收

- `session_close` 会关闭会话进程，但**不会杀掉远端未 kill 的后台任务**（`nohup`、`&`、
  systemd 服务、daemon）；
- `ssh_exec` 超时只会终止本地 `ssh` 子进程，远端命令可能继续运行；
- 被攻陷的远端主机可以故意留下进程。

运营建议：在远端使用 cgroup/systemd-run/超时包装器；定期巡检；不要假设关闭会话等于清理。

## 9. 审计轮转与多进程限制

- 轮转条件：活动文件非空且 `size + incoming > max_bytes`，或（默认）文件 mtime 日期与当前
  日期不同；
- 归档名严格为 `audit-YYYY-MM-DD[.N].jsonl`；单条超阈值记录仍整行写入，不拆分；
- 保留策略只删除严格命名的普通文件，不跟随符号链接，不删除活动 `audit.jsonl`；
- 跨进程没有协调：同一目录的多实例可能同时认为需要轮转，rename 竞争会导致归档名冲突
  由 `.N` 兜底，但记录顺序不保证全局一致。

## 10. 其他残余风险与运营建议

- **命令输出/文件内容**会进入模型上下文；“最小权限账户 + 远端数据分级”比本地过滤可靠。
- **信任首次使用**：`remote-mcp trust` 交互确认时务必核对指纹；`--fingerprint` 适合 CI，
  但需要独立可信渠道分发指纹。
- **配置注入**：`proxy_jump`、`identity_file`、`known_hosts_file` 由配置文件控制；保护配置
  文件权限，避免被低权限进程篡改。
- **工具参数日志**：日志与审计会记录命令哈希、字节数、退出事实，不记录命令原文/输出；
  但错误 details 可能包含脱敏后的 stderr 尾部，仍应按敏感信息处理。
- **依赖供应链**：`@napi-rs/keyring` 含原生绑定；升级前核对来源与完整性。
- **本机 `ssh` 可执行文件**：PATH 劫持可替换 ssh；使用绝对路径/受控 PATH，并保护本机账户。
- **拒绝服务**：并发上限、会话上限、输出上限与超时降低资源耗尽风险，但远端主机仍可拖慢
  命令；不要对不可信主机开放无上限会话。
- **审计失败不阻塞业务**：磁盘满/权限错误只 warn；需要强审计时监控该 warn 并告警。

## 11. 已知未覆盖项

- 没有远端命令沙箱、seccomp、cgroup 或文件系统隔离；
- 没有审计签名、远端集中转发、跨进程锁；
- 没有对 macOS/Linux keyring 的自动化集成测试（使用注入的替身验证映射）；
- 没有覆盖所有 shell/语言运行时的命令策略；策略绕过是开放问题；
- 没有在密码模式下做远端 sudo 成功/失败的真实 E2E（避免请求用户密码），只验证了
  凭据缺失时的零 spawn 行为。
